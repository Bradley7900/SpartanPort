# Ultrawide (21:9 and 32:9) — beta

**English** | [Português (Brasil)](#português-brasil)

The game's camera has a fixed *horizontal* field of view. Raising the render resolution to an ultrawide
size without touching the camera only crops the 16:9 picture top and bottom, so it looks zoomed in.
The `Resolution Patch - <width>x<height>` entries below fix that: the picture fills the whole screen,
the world keeps its proportions, and the vertical view is the same as at 16:9 (you simply see more to
the sides).

| Render resolution | Aspect | Status |
|---|---|---|
| 3440x1440 | 21:9 | **Tested in game** (3440x1440 monitor, build `6e72330e…`) |
| 2560x1080 | 21:9 | **Not tested** |
| 3840x1600 | 21:9 | **Not tested** |
| 5120x1440 | 32:9 | **Not tested** |

The author only has a 3440x1440 monitor. The other sizes are generated by the same code with other
numbers, but nobody has played with them yet. **If you try one, please say how it looks** (an issue or a
comment on the pull request): the resolution, what you see, and whether anything is cropped, stretched or
missing at the edges. If you need another size, see "Other resolutions" below.

## Using it

In the launcher, **Render resolution** → pick the size (or `render_resolution=3440x1440` in
`gow3.ini`, or the same list in the in-game menu), then **PLAY**. The patch asks for extra direct memory
(the Video Arena grows with the number of pixels); `run.py` sets that from the patch note, as for the
other resolution patches. Use a display or window of the same size (borderless is the easy way).

What you get:

- The world and the HUD fill the screen; characters keep their proportions.
- Menus are in the right proportion.
- **Cutscenes keep their borders.** They are pre-rendered 16:9 videos, so they play with black bars at
  the sides. Stretching them to fill the screen would distort the picture, and they cannot be re-rendered.
- At 32:9 the field of view is multiplied by 2 horizontally. It is rectilinear, so objects at the very
  edges look stretched, as in any game with a very wide field of view.

## What it changes

1. The render resolution, as the other `Resolution Patch` entries do, and the Video Arena size.
2. The display aspect ratio, two floats in the video mode (`16/9` → `width/height`).
3. The tangent `t` of the field of view, multiplied by `k = (width/height) / (16/9)` (43/32 at
   3440x1440), in the four places the cameras read it. The projection is `x = 2/t`, `y = 2A/t`
   (`A` = aspect ratio), so with the new `A` and `t·k` the vertical view stays the one of a 16:9 picture and
   the horizontal one widens. The same `t` feeds the culling vectors (two builders) and the standard
   camera's `tan(fov/2)`, so nothing is culled at the sides.

There is no room for a multiplication in place. Each of the four sites becomes a `jmp` into two chained
15-byte NOP pads between functions ("caves": the first runs the replaced instruction, the second
multiplies by `k` and jumps back), and a ninth pad holds the constant `k`. Every site and pad is found
by a signature (`Pattern`/`At`) like the other patches; a build that does not match skips the patch.

## Other resolutions

`tools/make_ultrawide_patch.py` writes the entry for any size (it needs the 6e72 `eboot.bin` and capstone):

```
python tools/make_ultrawide_patch.py path/to/eboot.bin patches/God_of_War_III_Remastered.xml 3840 1080 --write
```

The last two numbers are the width and the height. Then add the name to
`RESOLUTIONS` in `scripts/graphics_options.py` and `Resolutions` in `gpu/shim/gow3_graphics.h` (and the
labels in the launcher and `gpu/shim/gow3_overlay.cpp`). New sizes are marked "not tested" in the patch
note until they are added to `TESTED_IN_GAME` in the tool.

## Reference build addresses

The `Address` attributes of the new lines are addresses in the `6e72…` build (the author did not have
the `d85c8135…` build). The signatures are what is used. To turn them into the reference build's
addresses, which the reference test compares against, run with that build's `eboot.bin`, once per size:

```
python tools/make_ultrawide_patch.py --rebase path/to/eboot_d85c.bin patches/God_of_War_III_Remastered.xml 3440 1440
```

## Português (Brasil)

A câmera do jogo tem campo de visão *horizontal* fixo. Aumentar a resolução para um tamanho ultrawide
sem mexer na câmera só corta a imagem de 16:9 em cima e embaixo, e ela parece com zoom. As entradas
`Resolution Patch - <largura>x<altura>` corrigem isso: a imagem enche a tela, o mundo mantém as
proporções e a visão vertical é a mesma do 16:9 (você só vê mais dos lados).

| Resolução | Proporção | Situação |
|---|---|---|
| 3440x1440 | 21:9 | **Testado no jogo** (monitor 3440x1440, build `6e72330e…`) |
| 2560x1080 | 21:9 | **Não testado** |
| 3840x1600 | 21:9 | **Não testado** |
| 5120x1440 | 32:9 | **Não testado** |

Quem fez o patch só tem um monitor 3440x1440. Os outros tamanhos usam o mesmo código com outros números,
mas ninguém jogou com eles ainda. **Se você testar, conte como ficou** (numa issue ou no pull request): a
resolução, o que você vê e se algo aparece cortado, esticado ou faltando nas bordas.

**Como usar:** no launcher, **Render resolution** → escolha o tamanho (ou `render_resolution=3440x1440` no
`gow3.ini`, ou no menu do jogo) e **PLAY**. O patch pede memória direta extra; o `run.py` configura isso
pela nota do patch. Use uma tela ou janela do mesmo tamanho.

**As cutscenes continuam com bordas.** São vídeos 16:9 pré-renderizados, então tocam com barras pretas dos
lados. Esticá-los para encher a tela deformaria a imagem, e não dá para renderizá-los de novo. No 32:9 o
campo de visão horizontal fica multiplicado por 2, e os objetos nas bordas extremas parecem esticados,
como em qualquer jogo com campo de visão muito largo.
